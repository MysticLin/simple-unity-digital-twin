# 简单 Unity 数字孪生项目 · 四足机器人

一个低成本四足机器人（ESP32-C3）的**实时数字孪生**系统。
Unity 客户端通过 Wi-Fi 以 20 Hz 镜像机器人的姿态，也能反过来控制它。

> English version: [README.md](README.md)

---

## 它能做什么

| 方向 | 说明 |
| --- | --- |
| **真机 → Unity** | 四条舵机角度与整机状态通过 WebSocket 以 20 Hz 推送；Unity 还原姿态、车身倾角与表情 |
| **Unity → 真机** | 应用内面板可下发 17 个动作、4 个行进方向、21 种表情、6 种灯效 |
| **没有硬件也能跑** | 内置离线模拟器走同一条管线，无设备时也能演示与调试 |

固件侧为现有开源机器人固件**新增了一条遥测通道**（原固件只在事件发生时推送通知，
从不推送连续姿态），并修复了 ESP32-C3 单 I2S 控制器导致的启动崩溃。

## 技术要点

**1. 遥测协议（固件侧，+382 行）**

- 新增 `telemetry`（订阅，1~30 Hz）与 `snapshot`（单帧）两种消息
- **按连接独立订阅位** —— 手机网页不订阅就一帧都不发
- 主循环拆成 **50 ms 遥测节拍 + 200 ms 内务节拍**，姿态频率稳定且不用把 Wi-Fi/状态机提速 20 倍
- JSON 手拼进**预分配缓冲**（整帧只分配一次），不用 cJSON —— 因为板子的最大连续空闲块只有约 38 KB

**2. 姿态反解（Unity 侧）**

遥测里只有四个关节角，没有车身姿态。客户端做了三步：

```
关节角 → 足端位置（正运动学）
       → 四点拟合平面（Newell 法）
       → 车身旋转 = 父级偏航增量 × 静止参考姿态 × 贴地倾角
```

**3. 表情重建**

机器人用 8 个参数的"眼睛模型"画出 21 种表情。Unity 端**照抄同一套参数与数学**
（圆角矩形有符号距离场、眼皮切割），保证两边表情一致，而不是"看起来差不多"。

**4. 任意模型可绑定**

绑定器会实测模型的朝向轴、腿的顺序与腿长，然后自动重绑；只要模型满足绑定契约
（每腿一个枢轴、90° 竖直向下），任何 FBX 都能直接用。

## 协议

| 类型 | 方向 | 作用 |
| --- | --- | --- |
| `hello` | 设备 → 客户端 | 连接问候，并声明 `"telemetry": true` |
| `telemetry` | 客户端 → 设备 | 订阅：`{"type":"telemetry","hz":20}` |
| `telemetry` | 设备 → 客户端 | 姿态帧（见下） |
| `snapshot` | 客户端 → 设备 | 只取一帧，不订阅 |
| `ping` / `pong` | 双向 | 往返时延测量（原样回传 `t`） |
| `action` | 客户端 → 设备 | 17 个动作名（`stand`、`sit`、`wave` …） |
| `drive` | 客户端 → 设备 | `none` / `forward` / `backward` / `left` / `right` |
| `emotion` | 客户端 → 设备 | 21 个表情名或 `auto` |
| `lamp` | 客户端 → 设备 | `on` / `off` / `breathe` / `rainbow` / `flow` / `flash` |
| `speed` · `trim` · `chat` | 客户端 → 设备 | 调速、舵机微调、语音对话开关 |

姿态帧：

```json
{"type":"telemetry","t":123456,"state":"idle","voice":false,"emotion":"neutral",
 "action":"stand","busy":false,"drive":"none","speed":100,
 "legs":[90,90,90,90],"trims":[0,0,0,0],
 "lamp":{"on":true,"mode":2,"brightness":60,"speed":100,"r":255,"g":107,"b":53}}
```

`legs` 是**逻辑角**（`90` = 腿竖直向下，`>90` = 向前摆）。右侧舵机的镜像在固件内部完成、
不会通过网络传输 —— 所以客户端**不能再镜像一次**。

## 快速开始

### Unity 端

1. 新建 3D 项目（在 Unity 2022.3 上验证）
2. 把 `unity/*.cs` 拷进 `Assets/`
3. 搭场景：
   - 空物体 `Dog`，挂 `DogClient` + `DogBodySolver` + `DogSimulator` + `DogControlPanel`
   - 把你的四足 FBX 拖成子物体，然后跑菜单 **Tools ▸ 适配我自己的模型**
4. `DogClient.deviceHost` 填设备 IP；没有硬件就勾上 `offlineSimulation`
5. 进 Play

> 没有模型时，菜单 **Tools ▸ 生成孪生骨架** 会生成一只占位模型，可先验证整条链路。

### 固件端

```bash
# 先拿到上游工程（见"致谢"）
git apply firmware/digital-twin.patch
idf.py set-target esp32c3
idf.py build flash monitor
```

或者直接把 `firmware/files/` 里 4 个文件覆盖到对应位置。

## 已知限制

| 项 | 说明 |
| --- | --- |
| **音频输入不可用** | ESP32-C3 只有一个 I2S 控制器，而本板是 I2S 麦克风 + I2S 功放且采样率不同（16k/24k），无法同时工作。固件已改为**优雅降级**（不再开机 abort）：扬声器可用、麦克风禁用 |
| 唤醒词 | 当前配置未启用（日志显示 `WakeNet: no`） |
| 位置是估算量 | 遥测不含位置，客户端靠指令积分，长期会漂移 |
| 插值与帧率相关 | 姿态插值用固定每帧系数，帧率越低滞后越大（已实测记录，未修复） |
| 单设备 | 一个客户端实例对应一台设备 |
